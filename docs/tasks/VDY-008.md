6. v1–v6 synthetic round-trip/negative tests, typecheck/lint/test/Expo Doctor/Android export, R3 security review ve mümkünse tek gerçek platform smoke; kayıtları güncelle ve PR #22'ye draft aç.

## Uygulama ve güvenlik kararları

- Expo SDK 58'in `expo-sqlite` backup/serialization API'leri tutarlı in-memory kopya üretmek için kullanılıyor; canlı DB dosyası ham olarak kopyalanmıyor. Uygulama provider'ı bakım kilidi altında kapatılıp yeniden açılıyor; mevcut repository işlem kuyruğundaki bekleyen yazımlar tamamlanmadan yedek/restore/wipe başlamıyor.
- Yedek biçimi sürümlü, parola politikası 12–128 Unicode karakter, PBKDF2-HMAC-SHA256 600.000 tur, 16 bayt rastgele salt, 12 bayt nonce ve Expo Crypto native AES-256-GCM AEAD. Başlık da AAD ile doğrulanıyor. Format/uzunluk sınırı ve parola hataları hassas içerik göstermeyen genel UI mesajlarına çevriliyor.
- Restore önce bellekte decrypt edilir, formatı, kaynak user_version 1–6, integrity check, foreign key ilişkileri ve canonical migration şeması doğrulanır. Eski sürüm yalnız staging kopyasında v6'ya yükseltilir. Canlı DB ile staging ve rollback arasında doğrulanmış, marker'lı swap kullanılır; rollback kopyasının şema/FK/integrity, satır sayısı, serialize parity ve SHA-256 kontrolü tamamlanmadan prepared state'e geçilmez. Açılış recovery aynı kontrollerle fail-closed çalışır.
- Silme, açık iki aşamalı onaydan sonra boş v6 DB'ye doğrulanmış swap yapar. Flash depolamada forensic overwrite garanti edilmez; UI bu sınırı açıkça belirtir.
- `expo-crypto@58.0.7`, `expo-document-picker@58.0.4`, `expo-file-system@58.0.13`, `expo-sharing@58.0.22`, `@noble/hashes@2.4.0` SDK58 uyumlu tam sürümlere sabitlendi. Testte gerçek/sentetik kişisel ücret veya ödeme verisi yok.
