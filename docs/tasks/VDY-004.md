## Kapsam

- Create/edit/list/delete actual work records; each has UTC start/end instants, IANA timezone, break minutes, optional note, and optional planned-cycle/date association.
- Plan association is a snapshot/reference only: changing cycle entries, overrides, or shift templates must not alter/delete the work record. Planned hours are informational and no pay/legal overtime meaning is added.
- Manual unscheduled records are supported. Overnight ranges use distinct start/end local dates in the form.
- Same-user time overlaps are rejected with a clear error; adjacent intervals are allowed. Never shift/delete existing records to resolve conflict.
- Additive v3 SQLite migration with v1/v2 preservation, CHECK/FK/index constraints, transaction-safe repository CRUD, and race-safe overlap validation through the existing per-connection queue.
- Work screens linked from Today and selected Calendar day. No SQL in UI; existing schedule repository/domain projection remains the source of plan context.

## Decisions / validation

- Persist canonical UTC ISO instants plus the IANA timezone used to enter/display them. Local date/time input is resolved explicitly in that zone; nonexistent/ambiguous local wall times are rejected instead of silently normalized.
- Store total break duration in integer minutes. Require integer `0 <= breakMinutes <= elapsedMinutes`; no inferred pay treatment. Break intervals are outside this task's minimum data shape.
- Interval overlap uses half-open range semantics: `existing.start < new.end && existing.end > new.start`; exact boundary adjacency is allowed. On create/update, validate inside the same repository transaction; exclude the edited record itself.
- Optional `plannedCycleId` uses `ON DELETE SET NULL` so removing a schedule cannot delete the actual record; `plannedLocalDate` is retained as the link context. No cascade from plan edits.
- Only synthetic test data; no diagnostics/test fixtures in production source.
